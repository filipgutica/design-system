# Design decisions

Each entry records a choice this language made, the options it rejected, and why. Read it before you change a component, so a new project does not try a rejected option again. [Component specs](components.md) hold the values; this file holds the reasons.

| Decision | Layer | Chosen | Rejected, and why | Guarded by |

| Units | Core | Type (`--text-*`), spacing (`--space-*`), and control and row heights (`--control-*`, `--row`) are rem, as are the page literals that size text, padding, gaps, and line heights. Each equals its old pixel value at the default 16px root, so the default render does not change. Hairlines, focus rings and their offsets, shadows, fixed icon and box sizes, layout widths, and radii stay px. Media query breakpoints stay px and are out of scope here. | All px: text and controls ignored the reader's browser font-size setting. All rem: 1px hairlines and the 2px focus ring would grow or round to uneven widths. | rem sizes: `tests/design-foundations.test.mjs` "type, spacing, and control sizes are rem on every page, in tokens.css, and in the report stylesheet" |

## Token names

The 2.0.0 token rename, in the earlier version series (see Versioning), renamed 56 short names to the names `@filipgutica/ui` already declared. No value changed. Each `tokens.css` line before the rename named its ui variable in a `ui:` comment, and that variable became the line's name. Where a comment named several, the first one did.

To update a page or stylesheet that still uses the old names, run `node scripts/rename-tokens.mjs <file>...`. It reads the table below. A test fails when an old name appears in `language/` outside this table.

Name a new token by these rules:

- Give it one name. `tokens.css`, the class flavour, and `@filipgutica/ui` all declare it under that name, with no alias.
- Use Tailwind 4's theme namespaces where one fits: `--color-<role>` for a colour, `--shadow-<role>` for a shadow, `--radius-<role>` for a radius, `--font-<role>` for a font family, and `--text-<step>` for a type size. Other families keep their prefix, such as `--space-*`, `--control-*`, `--weight-*`, and `--duration-*`.
- Name the role, not the value: `--color-error`, not `--color-red`.
- A component role that always has the same value as a general token is a ui role in the token JSON's `library.roles`, listed after the general name in its `ui:` comment. It is not a new `tokens.css` line.
- Do not reuse an old name from this table.

## Known gaps

- Field focus is a 1px `--color-accent` edge with a faint 2px inset line. The edge reaches 3:1 for a focus indicator (WCAG 1.4.11): 6.61:1 against the light field fill and 6.26:1 against `--color-bg`, and 8.43:1 and 8.31:1 in dark. It is thinner than the 2px perimeter that the WCAG 2.2 AAA focus appearance criterion (2.4.13) asks for; the inset line, at 18% of the accent, does not reach 3:1 on its own.
- In forced colors (high contrast), an invalid field shows the system edge, not the `--color-error` edge, focused or not; the error text carries the state. A visible high-contrast invalid edge needs an error colour validated against high-contrast fills.
